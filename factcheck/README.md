# `factcheck/`

> **canonical** — the decision lives here; there are to be no copies

Two documents, and everything they are about.

    METHOD.md   the technology — three layers, the laws of a work order,
                gates, sources, measurement. Not about ESP32; this is what
                lifts onto another book.

    REPORT.md   the fact-check of *this* book: how much is checked,
                against what, what is left. Generated by
                `factcheck/tools/report.py`.

Read `METHOD.md` for the method, `REPORT.md` for the state. Nothing else
here needs opening to understand either.

## Everything else, by how long it lives

    tools/         the fact-check tools. Book-building tools stay in the
                   repository's own `tools/`; nothing imports across.

    cards/         one registry file per book file, mirroring the book
    evidence/      the evidence records themselves
                   — permanent: these grow with the book and are never
                     regenerated

    reports/       the detail behind REPORT.md, plus the live registries
                   REFUTED.md and UNREACHABLE-SOURCES.md
                   — regenerated: editing by hand only moves the next diff

    work/          queues, triage, runs, snapshots — state between waves
                   — transient: all of it is disposable

    archive/       spent work
                   — frozen: nothing deleted, translated or renamed

    source-cache/  the source documents as downloaded. **Not in git** —
                   a local arrangement, ignored by `factcheck/.gitignore`.
                   `MANIFEST.md` IS in git: URL, name, size, sha256, date
                   for every file. That is the reproducibility record, and
                   it weighs kilobytes against the cache's 136 MB.

That grouping is the rule for where a new file goes: ask how long it
lives, not what it is about.

## Starting another book

    factcheck/tools/newbook.py ../next-book

It copies `METHOD.md` and the tools, creates the directories, writes a
starter README — and then **runs the new tree's own self-checks**, failing
if they fail.

The last step is the point. What travels used to be a sentence in this
file, and a sentence drifts: three times in this project a document
promised something the code did not do, and each was found by someone
trying to *use* the promise, never by reading it. Provisioning is now the
test of its own claim.

It deliberately carries no evidence, cards, reports, cache or archive. A
new book starting with those would begin by inheriting another book's
findings — the self-reference defect at the largest possible scale.

## Why the directory looks like this

It held thirty-one documents and twenty-one directories, nine of them the
same kind of thing. Then it was cut too far the other way — everything
swept behind one directory called `data`, a name that accepts anything and
therefore says nothing.

> The root shows what a reader needs and what travels to another book.
> Everything else lives in a directory named after how long it lives.

Five checks hold that shape, and each one broke at least once while it was
being built: `doc_kind` (kind markers against reality), `language` (the
technology is English, the book is not), `naming` (transliteration, a
ratchet that may only shrink), `paths` (every literal path resolves), and
`docs` (nothing in this root but the three documents — including a tool
that merely *intends* to write here).

## The book itself is not here

`manual/`, `dodatky/`, `kartky/` and `inserts/` exist twice on purpose: at
the repository root they are the book, and under `cards/` they are the
registry that mirrors it, one file to one file. Card names stay Ukrainian
because they cite the book, and the book is the product.
