# Рецензування

Довідник проходить два типи наскрізних перевірок. Кожна сесія лишає файл
у цьому каталозі з датою й часом у назві.

```
reviews/YYYY-MM-DD-HHMM-review-<обсяг>.md      рецензія
reviews/YYYY-MM-DD-HHMM-factcheck-<обсяг>.md   фактчекінг
```

## Рецензія

Читання на рівні **окремого підрозділу**, не файлу. Що перевіряється:

- **фактична коректність** — усе, що можна звірити, іде у фактчекінг;
- **внутрішня узгодженість** — чи не суперечить розділ іншому розділу;
- **правильність перехресних посилань за змістом**, а не лише за
  існуванням якоря: посилання може вести на наявний розділ і при цьому
  не на той;
- **повтори** (Р10): одна тема не існує двома незалежними текстами;
- **відповідність підсумку тексту** — чи справді в «Що з цього треба
  запам'ятати» те, що в розділі;
- **прогалини** — те, чого в розділі бракує, щоб ним можна було
  скористатися;
- **мова й типографіка**.

Механічну частину знімає `tools/review.py`, щоб читання йшло на суть.

## Фактчекінг

Кожне твердження, яке читач перевірятиме перед тим, як довіритися,
звіряється з **першоджерелом**: заголовки ESP-IDF, документація
Espressif, репозиторії проєктів. Результат — у `docs/fakty.md` разом із
джерелом і датою.

Правило те саме, що в реєстрі фактів: **чого немає в реєстрі, те в
тексті подається з позначкою або не подається взагалі**.

## Що робиться зі знахідками

Кожна знахідка отримує реакцію, і це умова завершення сесії:

| Стан | Що означає |
|---|---|
| **виправлено** | правка внесена, у файлі сесії вказано яка |
| **свідомо лишено** | правка не потрібна, з поясненням чому |
| **винесено** | потребує окремої роботи; записано, де саме |

Знахідка без реакції — незавершена сесія. Короткі знахідки закриваються
на місці; туманні спершу доводяться до стану, у якому зрозуміло, що з
ними робити.

## Проведені сесії

| Файл | Обсяг | Знахідок |
|---|---|---|
| `…0327-review-01-kartky` | ярус 0: картки К1–К15 | 16 |
| `…0335-review-02-chastyny-I-IV` | розділи 00–15 | 7 |
| `…0345-review-03-chastyny-V-VII` | розділи 16–29 | 9 |
| `…0353-review-04-chastyny-VIII-XI` | розділи 30–49 | 14 |
| `…0402-review-05-chastyny-XII-XV` | розділи 50–63 | 9 |
| `…0409-review-06-dodatky-vkladyshi` | додатки A–H, вкладиші | 6 |
| `…0413-factcheck-01-systemnyy` | уся книга, по класах тверджень | 4 |

Разом **65 знахідок**, усі з реакцією. Тіло книги пройдено рецензією
повністю; фактчекінг пройдено як окремий системний прогін по класах
тверджень (числа, адреси, піни, виклики API, команди), а не по розділах.

## Що з цього стало постійним

Три знахідки перетворені на механічні перевірки, щоб клас помилки не
повернувся:

- **кирилиця всередині латинського слова в блоці коду** (`review.py`,
  перевірка `kyrylycya-v-kodi`) — знайдено кириличну «о» в URL
  усередині рядка C;
- **«шпаруватість» замість «коефіцієнт заповнення»** — це обернені
  величини; додано до переліку одруків разом із механізмом винятків для
  глосарія, де слово пояснюється;
- **інвентар перевірюваних тверджень** (`tools/claims.py`) — щоб
  наступна ревізія починалася з дифу, а не з нуля.

Два робочі правила, виведені з повторюваних знахідок:

1. **Виправивши виклик API чи число — шукати його по всій книзі.**
   Три знахідки поспіль були «хвостами» правок, що лишилися в
   ілюстративних проєктах і в таблицях додатків.
2. **Виправивши розділ — перевірити додатки, які його переказують.**
   Таблиця додатка не має контексту, який виправив би її сам.
