# Фактчекінг, прохід 9: суцільна звірка командного рядка

Дата: 2026-08-26. Метод той самий, що в проході 7 для API: узято **всі**
команди, які книга друкує в блоках коду, і звірено кожну з документацією
й вихідним кодом інструмента — не з пам'яттю.

Прохід 7 дав нуль виправлень. Цей дав три, з них одне грубе. Різниця
показова: API книга брала з готового коду прикладів, а команди —
набирала руками.

## Виправлення 1 (грубе): `merge-bin` без `--chip` не запускається

Книга друкує в п'яти місцях:

```
esptool merge-bin -o vyrib.bin --flash-mode dio --flash-size 4MB \
  0x1000 bootloader.bin 0x8000 partition-table.bin 0x10000 app.bin
```

Ця команда падає одразу. З розбору аргументів самого esptool:

```python
def merge_bin_cli(ctx, addr_filename, **kwargs):
    """Merge multiple raw binary files into a single flashable file."""
    if ctx.obj["chip"] == "auto":
        raise FatalError(
            f"Specify the --chip argument (choose from {', '.join(CHIP_LIST)})."
        )
```

І те саме в документації опцій: *«Binary image generation commands, such
as `elf2image` or `merge-bin`, require the chip type to be specified.»*

Причина механічна. Решта команд esptool працює через порт і визначає чип
сама; `merge-bin` порту не має — вона складає файл офлайн, і визначати
нема звідки.

**Чому це серйозно.** `merge-bin` — не екзотика в цій книзі, а основа
розділу 21 «Серійна прошивка» і рядок у двох картках ярусу 0. Тобто
команда, яку читач набере в полі з ламінованої картки, не працює.

Перевірено на самому розборі аргументів, а не лише на документації —
саме тому, що ціна помилки тут висока.

**Реакція.** Виправлено в п'яти місцях: розділи 17 і 21, додаток C,
картки К10 і К15. Побічна користь: `--chip esp32` тепер стоїть в одному
рядку з адресою `0x1000`, і зв'язок «цей чип — ця адреса» видно в самій
команді, а не в примітці збоку.

## Виправлення 2: `-z` нічого не прискорює

Таблиця прапорців у додатку C стверджувала:

| `-z` | стиснення при передачі: швидше й надійніше |

З вихідного коду:

```python
@click.option("--compress", "-z", is_flag=True,
    help="Compress data during transfer (default unless --no-stub is specified).")
@click.option("--no-compress", "-u", is_flag=True,
    help="Disable data compression during transfer (default if --no-stub is specified)")
```

Стиснення ввімкнене за замовчуванням. У звичайній команді `-z` не
змінює нічого.

Але прапорець не безглуздий: разом із `--no-stub` стиснення типово
**вимкнене**, і саме там `-z` щось означає. А `--no-stub` — це рівно той
випадок із клонами, який книга розбирає окремо. Тож уточнення практичне,
а не академічне.

Те саме стосується рядка `--before default-reset --after hard-reset`,
який книга подавала як «керування скиданням»: обидва — значення за
замовчуванням, писати їх немає сенсу. Таблицю прапорців перероблено на
ту, де перелічені значення, які справді щось міняють.

## Виправлення 3 (доповнення): `idf.py merge-bin`

Книга вчила лише ручного `esptool merge-bin` з адресами, набраними з
голови, — і сама ж поруч попереджає, що `0x1000` на S3 дає образ, який
прошивається без скарг і не стартує.

Тим часом ESP-IDF має:

> The command `idf.py merge-bin` will merge the bootloader, partition
> table, the application itself, and other partitions (if there are any)
> **according to the project configuration** and create a single binary
> file `merged-binary.[bin|hex]` in the build folder.

Це прибирає цілий клас помилок: адреса бутлоадера, чип, режим і частота
флешу беруться з конфігурації того самого проєкту, який щойно зібрано.

**Реакція.** Додано в розділи 17 і 21, додаток C і картки К10, К15 із
явним правилом: **є проєкт — `idf.py merge-bin`; є лише `.bin`-файли —
`esptool --chip … merge-bin`**.

## Доповнення: `--after watchdog-reset` для плат із native USB

Симптом «прошилося, а застосунок не стартував, чип сидить у
завантажувачі» книга не розбирала, хоча на S3 і C3 із native USB він
звичайний: фізичної лінії `RTS` там немає.

> `--after watchdog-reset` hard-resets the chip by triggering an internal
> watchdog reset. … Use this if a chip is getting stuck in download mode
> when using the default reset method in USB-Serial/JTAG mode. Using this
> may cause the port to re-enumerate on Linux (`/dev/ttyACM0` →
> `/dev/ttyACM1`).

Умову застосовності взято з самої директиви, а не вгадано: режим є на
S2, S3, C3, P4, C5 і новіших, і його немає на classic, C6 та H2 — так і
записано. Побічний ефект із перелічуванням порту названо теж, бо без
нього читач вирішить, що плата зникла.

## Що звірено без розбіжностей

Усе інше. `read-flash 0 ALL` збігається з прикладом документації
дослівно; `chip-id`, `flash-id`, `read-mac`, `erase-region`,
`verify-flash`, `write-flash` — усі є; `idf.py build` існує як псевдонім
до `all` (`'aliases': ['build']` у `core_ext.py`); `app-flash`,
`fullclean`, `size-components`, `size-files`, `coredump-info`,
`coredump-debug`, `openocd`, `gdb`, `reconfigure` — усі в переліку дій;
`add-dependency` — у менеджері компонентів.

Заразом підтверджено дві дрібниці з інших розділів: типова швидкість
esptool — 115200, а 74880 названо *«usual baud rate used by the
ESP8266»*. Друге підтверджує картку К6 з іншого боку, ніж прохід 8.

## Знахідка про сам процес: картка перелилася на другу сторінку

Після правок збірка карток дала 16 сторінок замість 15. Причина — К15:
доданий рядок вивів її за межі аркуша.

Це порушення не орієнтиру, а **фізичної умови** з `docs/DESIGN.md`:
картка ярусу 0 друкується на аркуші й ламінується; те, що не влізло в
аркуш, карткою вже не є.

Виправлено за тим самим правилом, яке ця умова й передбачає (Р10):
глибину винесено, факт лишився. На К15 тепер один рядок —
`idf.py merge-bin`, — а ручний варіант із адресами живе на К10, у
розділі 21 і в додатку C, куди картка й посилається.

### Чому це стало окремою перевіркою

`tools/budgets.py` рахує слова, і на цій картці не спрацював би: слів
стало навіть менше (248 → 247), а сторінок більше. Переливається картка
не від обсягу тексту, а від верстки — таблиця на рядок довша дає ту саму
другу сторінку при тому самому обсязі.

Тому перевірка тепер стоїть там, де вона взагалі можлива, — **після
справжнього збирання**. `tools/build.py` після компіляції карток питає в
Typst сторінку початку кожної картки й порівнює з наступною:

```
✗ k15-seriyna: 2 сторінки — картка мусить бути одна. Ділити навпіл
  або виносити глибину в додаток (docs/DESIGN.md, Р10), не викидати факт
```

Збирання завершується кодом `1`. Перевірку випробувано штучним
переповненням: спрацьовує, а на чистому дереві мовчить.

Мітку в шаблон додано метаданими (`<pochatok-kartky>`) — вона нічого не
друкує, і без неї сторінку початку картки ззовні не дістати.
