# Політика авторства

Умова проєкту: **у публічній історії й у друкованому тексті немає жодних
слідів інструментів-асистентів.** Автор довідника — одна людина, і історія
репозиторію має це відображати без застережень.

Політика не декларативна: вона виконується git-хуками, які блокують коміт
і push. Обійти їх можна лише свідомо (`--no-verify`) — випадково не вийде.

## Канонічна ідентичність

```
Iaroslav Voitovych <yaroslav.voytovych@gmail.com>
```

Джерело істини — `.githooks/identity.conf`. Значення підставляються в
**обидва** поля кожного коміту: `author` і `committer`. Зміна цього файлу —
свідоме рішення власника.

## Три правила

1. **Жодних записів співавторства.** У повідомленні коміту не може бути
   трейлерів `Co-authored-by:`, `Assisted-by:` та подібних — незалежно від
   того, чию адресу вони несуть.
2. **Author і committer звірені.** Обидва поля кожного коміту, що виходить
   на remote, дорівнюють канонічній ідентичності. Не «author правильний, а
   committer якийсь» — обидва.
3. **Текст чистий.** У `.md`, `.typ`, `.yaml`, коді й Makefile немає назв
   інструментів-асистентів. Довідник іде в друк; у ньому їм не місце.

## Як це працює

| Хук | Коли | Що перевіряє |
|---|---|---|
| `.githooks/commit-msg` | при кожному коміті | повідомлення на заборонені патерни |
| `.githooks/pre-push` | перед виходом на remote | author, committer і повідомлення **кожного** коміту в діапазоні; вміст тексту |

Спільна логіка і перелік патернів — `.githooks/attribution-lib.sh`.

Хуки лежать у репозиторії, а не в `.git/hooks`, тому вони версіонуються
разом з текстом і діють у будь-якому клоні. Умова активації в новому клоні —
один раз виконати:

```sh
make setup
```

Це виставляє `core.hooksPath`, ідентичність і вимикає підпис комітів.

## Підпис комітів

`commit.gpgsign` у цьому репозиторії вимкнено свідомо. Наявний у середовищі
ключ підпису зареєстрований на сторонню адресу; підписати ним коміт означало
б поставити цю адресу в поле `committer` і тим самим порушити правило 2.
Підтверджена ідентичність автора важливіша за значок «Verified».

Якщо потрібен підпис — заведіть власний ключ на адресу з `identity.conf` і
ввімкніть `commit.gpgsign` знову; правило 2 при цьому виконується.

## Якщо push відхилено

Хук друкує конкретні поля, що не збіглися, і sha комітів. Виправлення:

```sh
# верхній коміт
git commit --amend --no-edit --reset-author

# діапазон комітів
git rebase --exec 'git commit --amend --no-edit --reset-author' <base>
```

`--reset-author` переписує обидва поля — і `author`, і `committer` —
значеннями з поточного `git config user.*`, тобто канонічними.
