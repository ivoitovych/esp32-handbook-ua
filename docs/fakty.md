# Реєстр звірених фактів

Кожен факт у довіднику, який може застаріти або який читач перевірятиме
перед тим, як довіритися, реєструється тут: значення, джерело, дата звірки.

Правило: **якщо факту немає в цьому реєстрі — у тексті він подається з
позначкою «звірити» або не подається взагалі.** Довідник, у якому не видно
різниці між звіреним і згаданим з пам'яті, у полі гірший за відсутність
довідника.

Формат рядка: значення · джерело · дата звірки.

## Тулчейн

**ESP-IDF — поточний stable: v6.0.2.**
Підтримка гілки v6.0 — до 2028-09-20.
Джерело: `espressif/esp-idf`, `SUPPORT_POLICY.md`; ESP-IDF Programming Guide
v6.0.2, розділ «ESP-IDF Versions». Звірено 2026-08-26.

**Термін підтримки релізу — 30 місяців від дати stable.**
Окремого статусу LTS не існує: 30 місяців має кожен major і кожен minor
реліз однаково. Це важливо, бо в форумах трапляється хибне «v5.x — це LTS».
Джерело: `espressif/esp-idf`, `SUPPORT_POLICY.md`. Звірено 2026-08-26.

**esptool — поточна версія: v5.3.1** (випущено 2026-06-26).
Джерело: `espressif/esptool`, `CHANGELOG.md`. Звірено 2026-08-26.

**esptool v5 змінив синтаксис командного рядка — це ламає старі інструкції.**
Дві зміни, обидві незворотні для копіювання команд з інтернету:

1. Підкреслення замінено на дефіси: `write_flash` → `write-flash`,
   `chip_id` → `chip-id`, `flash_id` → `flash-id`, `erase_flash` →
   `erase-flash`, `read_flash` → `read-flash`, `merge_bin` → `merge-bin`.
2. Суфікс `.py` більше не потрібен: `esptool.py` → `esptool`,
   `espefuse.py` → `espefuse`, `espsecure.py` → `espsecure`.

Практичний наслідок для читача: переважна більшість інструкцій в мережі
написана під v4 і не працює дослівно на v5, і навпаки. У довіднику команди
подаються в синтаксисі v5, а різниця з v4 називається окремо.
Джерело: `espressif/esptool`, `CHANGELOG.md`, розділ v5.0. Звірено 2026-08-26.

**Arduino core для ESP32 — поточна версія: 3.3.11** (опубліковано 2026-07-22).
Джерело: `espressif/arduino-esp32`, сторінка релізів. Звірено 2026-08-26.

## Карта флешу

**Зсув другого бутлоадера залежить від сімейства чипа.**

| Сімейство | Зсув бутлоадера |
|---|---|
| ESP32 (classic) | `0x1000` |
| ESP32-S2 | `0x1000` |
| ESP32-S3 | `0x0` |
| ESP32-C3 та новіші RISC-V | `0x0` |

Причина різниці: у classic і S2 проміжок `0x0`–`0x1000` відведено під
потреби ROM-бутлоадера, у пізніших сімействах — ні.

Практичний наслідок: команда `write-flash 0x1000 bootloader.bin`,
скопійована з інструкції для ESP32 classic, кладе бутлоадер S3 не туди,
і плата не стартує. Це одна з найчастіших причин «прошив — і мовчить».
Джерело: ESP-IDF Programming Guide v6.0.2, «Bootloader» для esp32 і esp32s3.
Звірено 2026-08-26.

**Таблиця розділів — зсув `0x8000` на всіх сімействах.**
Займає цілий сектор флешу — `0x1000` (4 КБ), тому наступний розділ не може
починатися раніше ніж `0x9000`. Типовий ліміт розміру самої таблиці —
`0x7000` (28 672 байти) при зсуві бутлоадера `0x1000`.
Джерело: ESP-IDF Programming Guide v6.0.2, «Partition Tables».
Звірено 2026-08-26.
