# ESP32: практичний довідник

**Канонічний зміст — v1.0 (freeze)**
Репозиторій: `esp32-handbook-ua`. Ревізія: 2026-08-26 — друкується на титулі кожного зібраного PDF.

Довідник для досвідченого програміста без embedded-бекграунду, який завтра може опинитися в будь-якій ролі: писати код, паяти, прошивати серіями, лагодити чуже, зібрати робочий вузол «до ранку». Це не курс, а довідник з кількома маршрутами входу; лінійне читання — один із них.

---

## Зафіксовані рішення

Стислий перелік правил; обґрунтування і історія — у `docs/DESIGN.md`.

- **Р1. Три яруси, один репозиторій.** Картки ярусу 0 — першоджерело: пишуться першими як самостійні сторінки; основне тіло на них посилається і розгортає, не дублює.
- **Р2. Фокус по чипах.** Детально — ESP32 (classic) і S3; C3 — «дешевий малий»; S2, C6, H2 — оглядово; C2/C5/C61/H4/P4 — рядком у таблиці. Кожне chip-specific правило маркується областю дії: **[classic] [S3] [C3]**.
- **Р3. Ієрархія тулчейну.** Нормативне ядро — ESP-IDF (CLI) + офіційне розширення для VS Code; всі приклади зобов'язані працювати тут. Arduino core — швидке прототипування. PlatformIO + pioarduino — альтернатива з позначкою «community-форк».
- **Р4. Версії — у `toolchain-baseline.yaml`, не в тексті.** Таблиця в PDF генерується при збиранні; кожен рядок має статус `verified` / `UNVERIFIED`, незвірене друкується з позначкою.
- **Р5. Швидкопсувне — у датованих вкладишах** (`inserts/`): ринок, компонентний довідник, радіочастотні норми. Поза нумерацією; перевидаються окремо, нумерацію тіла не зачіпають.
- **Р6. Межі змісту.** Стандартна embedded-інженерія: залізо, код, протоколи, периферія, живлення, ремонт. Інтеграція зі зброєю і схеми ініціювання не розглядаються. ESP32 подається як допоміжний (companion) контролер збоку від основної системи.
- **Р7. Крос-посилання — стабільні якорі, не номери.** Кожен розділ і картка мають слаг; маршрути в джерелах ведуть лише на якорі; номери в друкованому змісті генеруються. `make linkcheck` — обов'язковий крок до кожного коміту тексту.
- **Р8. Мовна політика.** Українська назва + канонічний англійський термін у дужках при першій згадці в розділі: «черги (queues)», «підтягування (pull-up)». Усталені терміни не перекладаються: brownout, watchdog, backtrace, strapping.
- **Р9. Обсяг — бюджет, не обіцянка.** Розділ: 1200–2500 слів, ≤2 схеми, ≤3 приклади коду. Картка: ≤400 слів, 1 схема, строго одна сторінка. `make` перевіряє бюджети разом з якорями.
- **Р10. Додатки — не паралельні тексти.** Кожен додаток — розширення відповідних карток з тих самих джерел: картка — польова верхівка (одна сторінка), додаток — повна версія (таблиці, покажчики). Одна тема ніколи не існує двома незалежними текстами.
- **Р11. Три маршрути не змішуються.** «Прошити партію готових плат», «писати прошивку» і «обслуговувати чужий пристрій» — різні задачі з різними шляхами; той, кому треба прошити двадцять плат, не проходить через FreeRTOS.
- **Р12. Нейтральне іменування.** Репозиторій `esp32-handbook-ua`, титул «ESP32: практичний довідник»; польова специфіка живе у змісті (діагностика, ремонт, корпуси), а не в назвах. PDF: `esp32-kartky.pdf`, `esp32-dovidnyk.pdf`, `esp32-proekty.pdf`.
- **Р13. Конкретні операційні факти — не в змісті.** Цифри струмів, частот, обмежень потужності живуть у розділах (зі scope і джерелом) або у вкладишах; зміст називає тему, не значення.
- **Р14. Ролі попередніх ітерацій:** повний надлишковий перелік тем → `docs/coverage-checklist.md` (аудит перед freeze кожної ревізії: тема відсутня — це рішення, не забудькуватість); обґрунтування і «що викинуто і чому» → `docs/DESIGN.md`; коротка карта книги → README.
- **Р15. Ліцензія (до підтвердження власником):** текст (`kartky/`, `manual/`, `dodatky/`, `inserts/`) — CC BY-SA 4.0; код (`kod/`) — MIT. Файли LICENSE кладуться першим комітом: без ліцензії довідник не можна легально ні друкувати, ні допрацьовувати.

## Ярус 0 — картки

`kartky/`, кожна — одна сторінка A4 під ламінування. **Ярус 0 готовий тоді й лише тоді, коли готові всі К1–К12** — це визначення завершеності релізу R0. К1 — перша сторінка ярусу.

| Картка | Якір |
|---|---|
| **К1.** Тріаж невідомої плати: маркування, живлення, `chip_id`/`flash_id`, дерево рішень | `{#k-triazh}` |
| **К2.** Збереження стану перед втручанням: фото, схема з'єднань, дамп флешу, вимірювання | `{#k-stan}` |
| **К3.** Підключення до ПК: кабель → драйвер → порт → права | `{#k-pidkl}` |
| **К4.** Download mode вручну (BOOT + EN); коли авторесет не спрацьовує | `{#k-boot}` |
| **К5.** Прошивка готового образу: `write_flash`, адреси, три образи, перевірка | `{#k-proshyvka}` |
| **К6.** Читання boot-логу: що означає кожен рядок | `{#k-bootlog}` |
| **К7.** Guru Meditation і backtrace за 60 секунд | `{#k-panika}` |
| **К8.** Топ-15 несправностей: симптом → причина → дія | `{#k-symptomy}` |
| **К9.** Пінаути ключових плат, великим шрифтом | `{#k-pinouty}` |
| **К10.** Шпаргалки команд: esptool, idf.py, монітор | `{#k-komandy}` |
| **К11.** ⛔ Ніколи: eFuse і Secure Boot наосліп, [classic] GPIO 6–11, 5 В на пін, erase без дампа | `{#k-nikoly}` |
| **К12.** Польовий комплект і закупівельний список | `{#k-komplekt}` |

**Друга хвиля** (не блокує готовність ярусу 0): **К13** — живлення: пошук несправності `{#k-zhyvlennya}`; **К14** — сумісність логічних рівнів `{#k-rivni}`; **К15** — чек-лист серійної прошивки `{#k-seriyna}`.

# ЗМІСТ ОСНОВНОГО ТІЛА

## Вступ

**00. Про цей довідник** `{#pro-dovidnyk}`
- Для кого; що вважається відомим (C/C++, git, командний рядок), що ні (все «залізне» — з нуля)
- Межі змісту; таблиця версій (генерується з `toolchain-baseline.yaml`); дата ревізії
- Позначки: ⚡ живлення · ⚠ граблі · 🛒 закупівля · ⛔ незворотне · [classic] [S3] [C3] область дії
- Маршрути читання (ведуть на якорі; номери — лише в друкованому змісті):
  - «дали невідому плату / пристрій» → `{#k-triazh}` → `{#zberezhennya-stanu}` → `{#triazh}` → `{#chuzha-proshyvka}`
  - «треба тільки прошити» → `{#k-pidkl}` → `{#k-proshyvka}` → `{#esptool}`
  - «прошити партію» → `{#seriyna}` → `{#k-seriyna}`
  - «лагодити чуже» → `{#k-stan}` → `{#triazh}` → `{#symptomy}` → `{#polova-diagnostyka}`
  - «писати код» → `{#idf}` → `{#struktura}` → `{#freertos}`, далі частини IX–XI
  - «паяти і збирати» → `{#elektronika}` → `{#payannya}` → `{#korpus}`
  - «щось робоче за дві години» → `{#shvydki-shlyakhy}` → `{#proj-monitor}`
- Мовна політика; стартовий кошик → картка К12 і вкладиш ринку

## Частина I. Платформа

**01. Що таке ESP32 і коли його брати** `{#platforma}`
- Espressif і екосистема; три рівні: кристал (SoC) → модуль (WROOM/WROVER) → плата розробки
- Чесне порівняння з Arduino AVR / STM32 / RP2040 / Raspberry Pi; де ESP32 недоречний
- Де жити: документація, TRM, datasheet, форуми

**02. Лінійка чипів і правило фокуса** `{#chipy}`
- Правило Р2 в дії; порівняльна таблиця: ядра (Xtensa/RISC-V), частота, RAM/PSRAM, радіо, USB, периферія, ціна
- Сумісність коду між сімействами: що переноситься, що ні
- Рекомендації: типова задача → конкретний чип

**03. Архітектура SoC** `{#soc}`
- Xtensa LX6/LX7 проти RISC-V; двоядерність, FreeRTOS «з коробки»
- Пам'ять: ROM, SRAM (IRAM/DRAM), RTC RAM, зовнішня flash, PSRAM; кеш і memory map
- Тактування, RTC-домен, ULP-співпроцесор

**04. Периферія на кристалі — огляд** `{#peryferiya}`
- GPIO matrix: чому майже будь-який сигнал — на майже будь-який пін, і де межі
- ADC, DAC (де є), touch, RMT, LEDC, MCPWM, I2S, TWAI, USB OTG / USB-Serial-JTAG
- Зведена таблиця «що є в якому чипі»

## Частина II. Електроніка для програміста

**05. Електроніка за один вечір** `{#elektronika}`
- Напруга, струм, опір, потужність, закон Ома — рівно стільки, скільки треба
- Логічні рівні 3.3/5 В; конвертери рівнів і дільники; що саме спалює плату
- Підтягування (pull-up/pull-down), open-drain; земля і спільна земля; розв'язувальні конденсатори; MOSFET як ключ, захисний діод
- ESD; топ-5 способів убити плату за 10 секунд → картка К11

**06. Живлення і струмоспоживання** `{#zhyvlennya}`
- 3.3 В, VIN, межі бортового LDO; пікове споживання Wi-Fi і вимоги до джерела; чому «глючить від дешевого хаба»
- Brownout: як проявляється, як лікується
- Режими: active / modem sleep / light sleep / deep sleep / ULP — з реальними цифрами в тексті розділу
- Методика вимірювання споживання (USB-тестер, шунт)

**07. Розпіновка й обмеження GPIO** `{#gpio}`
- Strapping-піни; [classic] input-only 34–39; [classic] піни flash 6–11 — не чіпати; USB- і JTAG-піни
- [classic/S2] ADC2 конфліктує з Wi-Fi; DAC, touch
- Як читати pinout, і чому pinout плати важливіший за pinout чипа → картки К9

## Частина III. Плати й підключення

**08. Модулі, плати, анатомія девборди** `{#platy}`
- Модулі: WROOM-32, WROVER (PSRAM), S3-WROOM-1, C3-MINI; читання маркування; оригінали й клони
- Анатомія плати: LDO, USB-UART міст, схема авторесету DTR/RTS, кнопки BOOT/EN
- Плати: офіційний DevKitC V4 (38 пінів); DevKit V1 / DOIT-подібні — бувають 30- і 38-пінові, це різні плати; S3-DevKitC-1 (N8/N16R8), C3 SuperMini, D1 Mini ESP32, ESP32-CAM (+ окремий програматор); LilyGO / M5Stack / Heltec — оглядово
- Як розпізнати підробку (перемаркований чип, фейковий CH340, менша флеш — `flash_id`); стратегія уніфікації парку; конкретні позиції й ціни → вкладиш ринку

**09. Підключення до комп'ютера** `{#pidklyuchennya}`
- USB-UART мости: CP2102, CH340, CH9102 — драйвери Windows/Linux, типові проблеми
- Native USB у S3/C3: USB-CDC і USB-JTAG без мостів
- Кабелі data проти charge-only; права на порт, група dialout → картка К3

**10. Комплект інструментів** `{#instrumenty}`
- Мінімальний: мультиметр, паяльник, USB-UART, Dupont, макетка
- Розширений: логічний аналізатор, лабораторний БЖ, USB-ватметр, фен, JTAG-адаптер

## Частина IV. Інструментарій

**11. ESP-IDF + розширення VS Code — нормативне ядро** `{#idf}`
- Встановлення (Windows installer / Linux); філософія фреймворку
- `idf.py`: create-project, set-target, build, flash, monitor, menuconfig; компоненти, sdkconfig, component registry
- Розширення для VS Code: проєкт, build/flash/monitor, debug, IntelliSense; яку гілку брати

**12. Arduino core для ESP32** `{#arduino}`
- Що це під капотом (обгортка над IDF); де виграш, де стеля
- Граблі міграції 2.x → 3.x, сумісність сторонніх бібліотек

**13. PlatformIO і pioarduino** `{#pio}`
- Статус: чому офіційна platform-espressif32 застаріла і що таке pioarduino (community)
- `platformio.ini`: env, board, framework, build_flags; чому версію платформи треба пінити

**14. MicroPython, ESPHome, Wokwi — оглядово** `{#shvydki-shlyakhy}`
- Коли кожен із них — найкоротший шлях до робочого вузла; обмеження

**15. Вибір, поєднання, офлайн-комплект** `{#oflayn}`
- Матриця вибору; сценарій «прототип на Arduino → продукт на IDF»; один проєкт трьома тулчейнами
- Офлайн-комплект: що поставити й закешувати заздалегідь → додаток F

## Частина V. Прошивка

**16. Як завантажується ESP32** `{#boot}`
- ROM bootloader → другий бутлоадер → застосунок; таблиця розділів у цьому ланцюжку
- Вхід у download mode: strapping, BOOT/EN, авторесет → картка К4
- Що видно в консолі при кожному варіанті старту

**17. esptool** `{#esptool}`
- `chip_id`, `flash_id`, `read_flash`, `write_flash`, `erase_flash`, `merge_bin`, verify
- Offsets і три образи; Flash Download Tool для Windows → картка К5
- Типові помилки esptool і їх розшифровка

**18. Розділи флешу** `{#rozdily-fleshu}`
- Partition table: розбір CSV (nvs / phy_init / factory / ota_0,1 / storage)
- NVS; файлові системи: LittleFS проти SPIFFS проти FAT
- Як змінити розбивку і не зламати OTA

**19. OTA-оновлення** `{#ota}`
- Два app-слоти, otadata, rollback, відновлення після невдалого оновлення
- ArduinoOTA, оновлення з веб-сторінки, `esp_https_ota`; оновлення в полі без ПК

**20. Бекап, відновлення, «цеглинка»** `{#bekap}`
- Повний дамп флешу і заливка на іншу плату → картка К2
- Що реально можна вбити (eFuse), а що лікується завжди
- Boot loop за консоллю: покроковий алгоритм; коли erase_flash рятує, а коли його не можна

**21. Серійна прошивка партії** `{#seriyna}`
- `merge_bin` + скрипт; контроль після прошивки → картка К15
- Конфігурація per-device (NVS), маркування плат, журнал версій прошивок і конфігурацій

## Частина VI. Невідомий пристрій

**22. Збереження стану перед втручанням** `{#zberezhennya-stanu}`
- Фото, схема з'єднань, положення перемичок, вимірювання, дамп флешу, версія прошивки — до того, як щось чіпати → картка К2

**23. Тріаж невідомої плати** `{#triazh}`
- Маркування → визначення чипа/модуля/плати → datasheet і схема → допустиме живлення → USB/UART → boot-лог → перевірка GPIO
- Дерево рішень: від «що це?» до «що з цим можна робити» → картка К1

**24. Чужа прошивка: форензика** `{#chuzha-proshyvka}`
- Partition map живого пристрою; що лежить у NVS і файловій системі
- Build/version strings; пошук вихідників; відтворюване збирання (reproducible build)
- Що можна змінити без сорсів (конфігурація, ресурси), а що ні; ризики втручання

## Частина VII. Налагодження і діагностика

**25. Serial monitor і логування** `{#log}`
- Монітори: `idf.py monitor`, PlatformIO, Arduino IDE, minicom/putty; як зняти лог з невідомого пристрою → картка К6
- ESP_LOGx: рівні, теги, керування в runtime; лог у файл і на SD, кільцевий буфер

**26. Читання збоїв** `{#zboyi}`
- Guru Meditation: LoadProhibited, StoreProhibited, IllegalInstruction, InstrFetchProhibited → картка К7
- Backtrace і декодування (monitor, exception decoder, addr2line)
- Task WDT проти interrupt WDT; reset reasons; brownout reset; coredump у flash

**27. JTAG і покрокове налагодження** `{#jtag}`
- Вбудований USB-JTAG у S3/C3: breakpoint-и без жодного заліза
- OpenOCD + GDB у VS Code; [classic] ESP-Prog / FT2232 — чи воно того варте

**28. Апаратна діагностика сигналів** `{#analizator}`
- Логічний аналізатор + PulseView: I²C/SPI/UART наживо
- Коли потрібен осцилограф; що і де міряти мультиметром

**29. Симптомний troubleshooting** `{#symptomy}`
- Не бачить плату / немає порту / не входить у bootloader / flash failed / invalid header
- Boot loop / brownout / Wi-Fi мовчить / I²C не знаходиться / SPI не відповідає / GPIO поводиться дивно
- Працює від USB, але не від зовнішнього живлення; перегрів → додаток B, картка К8

## Частина VIII. Програмування

**30. Застосунок і модель пам'яті** `{#struktura}`
- `app_main` проти `setup`/`loop`; що відбувається до входу в main
- static / stack / heap, IRAM/DRAM, PSRAM; чому без динамічного виділення в циклі; фрагментація
- `volatile`, регістри, атомарність; розміри стеків задач

**31. FreeRTOS і конкурентність** `{#freertos}`
- Задачі (tasks), пріоритети, планувальник; черги (queues), семафори, м'ютекси, event groups, таймери
- ISR і задачі; два ядра, прив'язка до ядра (core affinity) — типові помилки синхронізації

**32. Надійність і обробка помилок** `{#nadiynist}`
- esp_err_t, ESP_ERROR_CHECK, assert-и; стратегія обробки помилок
- Watchdog як інструмент; безпечний стан; поведінка при зникненні живлення
- Реальний час без RTOS-фанатизму: що таке «вчасно» на 240 МГц

**33. Периферія з коду: GPIO, таймери, PWM, ADC** `{#peryferiya-kod}`
- GPIO і переривання, антидребезг; таймери
- LEDC (світлодіоди, серво), MCPWM (мотори), RMT (WS2812, вимірювання імпульсів)
- ADC: реальна точність, калібрування, боротьба з шумом

## Частина IX. Дротові інтерфейси

**34. UART, RS-485, Modbus** `{#uart}`
- Апаратні порти, ремапінг пінів, консоль проти вільних портів
- RS-485 через MAX485: напівдуплекс, керування напрямком; Modbus RTU — оглядово

**35. I²C** `{#i2c}`
- Фізика шини: підтягування, ємність, довжина проводів
- Сканер, конфлікти адрес, clock stretching; типові симптоми несправностей

**36. SPI** `{#spi}`
- Режими, швидкості, кілька пристроїв (CS), DMA; коли SPI, а коли I²C

**37. 1-Wire** `{#onewire}`
- Протокол, DS18B20, паразитне живлення, кілька датчиків на лінії

**38. CAN (TWAI)** `{#can}`
- Трансивери, термінатори; обмін між двома вузлами; обмін з «дорослим» контролером по CAN

## Частина X. Бездротовий зв'язок

**39. Wi-Fi** `{#wifi}`
- STA / AP / APSTA; збереження креденшелів, reconnect, RSSI і реальна дальність; provisioning
- Антени: PCB проти IPEX, розміщення, метал-корпус

**40. Мережеві протоколи** `{#merezha}`
- TCP/UDP, сокети; HTTP-клієнт і сервер, WebSocket, mDNS, SNTP
- MQTT: брокер, структура топіків, QoS; TLS на пристрої — мінімум

**41. Bluetooth і BLE** `{#ble}`
- Classic (SPP) проти BLE; [S3/C3] — тільки BLE
- GATT: сервіси, характеристики, notify; NimBLE; обмін з телефоном

**42. ESP-NOW** `{#espnow}`
- Peer-и, broadcast, шифрування, канали; співіснування з Wi-Fi
- Міст «багато датчиків → один приймач»; де виграє, а де ні

**43. LoRa та інші радіо** `{#lora}`
- SX1276 / SX1262 / RA-01 по SPI; антени й узгодження; point-to-point; LoRaWAN — оглядово
- Дозволені діапазони й обмеження потужності → датований вкладиш радіонорм
- 802.15.4 / Thread / Zigbee [C6/H2], Matter — оглядово

## Частина XI. Периферія

**44. Як підключити незнайомий модуль** `{#neznayomyy-modul}`
- Datasheet → допустиме живлення → логічні рівні → інтерфейс → адреса/протокол → бібліотека
- Мінімальний тест окремо від проєкту; що робити, коли бібліотеки немає

**45. Сенсори** `{#sensory}`
- Середовище: DS18B20, DHT22 — і чому BME280/SHT3x кращі; тиск, освітленість
- Відстань і рух: HC-SR04 (⚠ 5 В), VL53L0X, PIR; інерціальні: MPU6050, BNO055 — оглядово
- Аналогові: подільники, калібрування ADC; струм/напруга: INA219, ACS712
- GPS/GNSS по UART, розбір NMEA

**46. Дисплеї і введення** `{#dyspleyi}`
- OLED SSD1306/SH1106, TFT ST7789/ILI9341, e-paper; U8g2, TFT_eSPI / LovyanGFX; LVGL — оглядово
- Кнопки (антидребезг), енкодери, матричні клавіатури

**47. Ключі, реле, узгодження рівнів** `{#klyuchi}`
- Оптоізольовані реле, MOSFET low-side, біполярні; захисні діоди на індуктивностях
- 3.3 ↔ 5 В: коли конвертер обов'язковий; гальванічна розв'язка, спільна земля

**48. Двигуни й сервоприводи** `{#motory}`
- DC: DRV8833 / TB6612 / L298N — чому L298N застарів, але всюди продається
- Крокові: A4988/DRV8825 + NEMA17; 28BYJ-48 + ULN2003
- Серво: окреме живлення, спільна земля; плавність руху

**49. Карти пам'яті, камери, звук** `{#kamera}`
- microSD: SPI проти SDMMC; надійний запис при зникненні живлення
- ESP32-CAM (OV2640): живлення, прошивка, MJPEG; [S3] що змінюється, межі FPS і пам'яті
- I²S-мікрофон (INMP441), підсилювач MAX98357 — оглядово

## Частина XII. Безпека

**50. Безпека пристрою** `{#bezpeka}`
- Креденшели: чому дефолтні паролі — не варіант; зберігання ключів, NVS encryption
- TLS-мінімум: сертифікати, перевірка сервера
- ⛔ Flash encryption і Secure Boot: що це, коли треба, що незворотне; припущення про фізичний доступ

## Частина XIII. Збирання і супровід

**51. Паяння і монтаж** `{#payannya}`
- Інструмент і витратні; гребінки, дроти, THT; типові дефекти, як не відірвати площадку
- Роз'єми: JST, Dupont, гвинтові — і чому Dupont під вібрацією не тримає

**52. Від макетки до постійного монтажу** `{#montazh}`
- Межі breadboard; перфборд — робочий стандарт одиничних пристроїв
- Власна PCB: KiCad + виробництво — оглядовий наскрізний приклад

**53. Автономне живлення** `{#akum}`
- Li-ion/18650: заряд (TP4056 з захистом), BMS, безпека
- LDO проти buck/boost; тихе живлення для ADC; захист від переполюсовки
- Вимірювання заряду; бюджет енергії з deep sleep і його перевірка вимірюванням

**54. Корпус і захист середовища** `{#korpus}`
- Бокси, IP65+, кабельні вводи, strain relief
- Conformal coating, силікагель, конденсат; вібрація; температурні межі

**55. Польова діагностика й ремонт** `{#polova-diagnostyka}`
- Що і в яких точках міряти мультиметром (живлення, просадки, обриви, КЗ)
- Типові апаратні дефекти: регулятор, USB-роз'єм, флеш, антена, холодна пайка
- Від симптому до вузла; jumper-ремонт; заміна модуля / плати цілком

**56. Паспорт виробу і передача** `{#pasport}`
- Як описати схему так, щоб зібрав інший
- Паспорт: пінаут, живлення, порядок прошивки, налаштування, дії при збої
- Версіонування прошивок, changelog; інструкція оператору на одну сторінку

## Частина XIV. Від задачі до пристрою

**57. Постановка і архітектура** `{#vid-zadachi}`
- Входи/виходи, затримки, канал зв'язку, бюджет живлення, середовище, поведінка при відмові
- Вибір чипа і плати; блок-схема; план тестів і критерії приймання
- ESP32 як companion-контролер збоку від основної системи: обмін по UART/CAN, розділення відповідальності

**58. Прототип → тест → надійний вузол** `{#dovedennya}`
- Мінімальний прототип і тестова обв'язка; логування як інструмент доведення
- Зміцнення: fault handling, watchdog, recovery, постійний монтаж
- Документування результату → паспорт виробу (`{#pasport}`)

## Порядок релізів

| Реліз | Вміст | Формула |
|---|---|---|
| **R0** | К1–К12 повністю | картки в руках |
| **R1** | 09, частини V–VII (16–29) | підключити → прошити → визначити → прочитати лог → знайти несправність |
| **R2** | 00–08, частина IV (11–15), частини VIII–XI (30–49) | платформа, код, інтерфейси, периферія |
| **R3** | 50–58, проєкти 59–63, додатки, вкладиші, К13–К15 | безпека, збирання, інженерний процес, проєкти |

## Виробничі нотатки

- Перед freeze кожної major-ревізії — прогін по `docs/coverage-checklist.md`: тема є → де покрита; теми немає → це рішення чи забудькуватість.
- Незвірені рядки `toolchain-baseline.yaml` звірити до першого збирання `esp32-dovidnyk.pdf`; вкладиші збираються пошуком, не з пам'яті.
- Якщо стане відома конкретна плата на руках — картки К1 (таблиця живлення) і К9 переверстуються під неї в першу чергу.

*Разом: вступ + 63 розділи + 15 карток + 8 додатків + 3 вкладиші. Картки ≈ 15 стор.; основне тіло ≈ 200 стор. (бюджет); ярус 2 ≈ 40+ стор.*
