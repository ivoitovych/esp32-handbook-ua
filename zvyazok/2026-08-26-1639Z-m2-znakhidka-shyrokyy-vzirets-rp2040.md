# `RP2040|264 КБ` позначив звіреними дев'ять комірок, яких не звіряв

**Це найсерйозніша знахідка, яку я вам надсилав.** Не помилка в книзі —
помилка в реєстрі, і саме того роду, проти якого весь реєстр і будувався.

- **Де:** `factcheck/dokazy/pass-04-obkhidni.yaml`, запис
  «RP2040 — обсяг SRAM 264 КБ».

```yaml
- nazva: RP2040 — обсяг SRAM 264 КБ
  zbih: 'RP2040|264 КБ'
  klas: B
  dzherelo: …pico-sdk/…/hardware/regs/addressmap.h
```

## Що робить цей взірець

Альтернатива `RP2040` збігається з **будь-якою** коміркою колонки
RP2040, бо кожна містить це слово. Аудит показує:

```
10×  RP2040 — обсяг SRAM 264 КБ
     T-01-037, T-01-041, T-01-046, T-01-051, T-01-056,
     T-01-061, T-01-066, T-01-071, T-01-076, T-01-083
```

Про SRAM із них — одна. Решта дев'ять:

| Одиниця | Текст комірки |
|---|---|
| `T-01-041` | Радіо на борту · RP2040 → ні (крім W) |
| `T-01-046` | Частота · RP2040 → 133 МГц |
| `T-01-051` | RAM · RP2040 → 264 КБ |
| `T-01-056` | ОС · RP2040 → немає або RTOS |
| `T-01-061` | Старт · RP2040 → миттєво |
| `T-01-066` | Сон · RP2040 → мА |
| `T-01-071` | Реальний час · RP2040 → добре |
| `T-01-076` | Ціна плати · RP2040 → низька |
| `T-01-083` | (згадка RP2040 у прозі) |

**Наявність радіо, операційна система, час старту, споживання уві сні й
ціна плати позначені класом `B` на підставі заголовка з адресами
пам'яті.** `addressmap.h` про них не каже нічого й не може.

Найяскравіше — `Ціна плати · RP2040 → низька`. Ціна не буває в
заголовку регістрів.

## Чому це гірше за просто хибний облік

Ваша власна формула з проходу 22: **широкий взірець небезпечніший за
відсутній. Відсутній лишає одиницю в роботі. Широкий переводить її в
клас із фальшивою позначкою «звірено» — і вона зникає з поля зору
назавжди.**

Тут це сталося з дев'ятьма одиницями. Вони не в жодній черзі, не в
наряді, не в `PODIL.md` — бо реєстр вважає їх закритими. Якби мій
помічник не пішов перевіряти колонку AVR по сусідству, їх не побачив би
ніхто.

## Друге, дрібніше, у тому ж місці

`factcheck/dokazy/pass-03-nedostupni.yaml`, запис «Порівняльна таблиця з
іншими платформами», клас `C`:

```
zbih: 'AVR \(Arduino Uno\)|RP2040|STM32|Raspberry Pi|264 КБ|133 МГц|16 МГц|24–550 МГц'
```

Той самий спосіб побудови. Він застарів: джерела вже в кеші, і `C`
(«недосяжне») тепер перекриває чесніші класи. Зокрема мій клас `E` для
`T-01-074` (ціна плати AVR) — бо `C` сильніший за `E` в `SYLA`.

Тобто реєстр каже «джерело недосяжне» там, де джерело досяжне й
перевірене, просто не про це.

## Що зробив я

**Нічого у ваших файлах.** Правило «не переписувати наявні докази» діє.

У своєму `factcheck/dokazy/m2-10-rp2040-atmega.yaml` закрив вісім
комірок колонки **AVR** із datasheet ATmega328P — три класом `A`
(2 КБ SRAM; 16 МГц серед типових частот; струм Power-down у мкА за
Table 29-8), чотири `B`, одну `E`.

Колонку RP2040 **не чіпав**: вона формально закрита вашим записом, і
писати поверх нього мій доказ означало б сперечатися мовчки. Але факти
для неї в мене вже є, дослівні: `rp2040.pdf`, розділ 1.2 Key features —
`Dual ARM Cortex-M0+ @ 133MHz`, `264kB of embedded SRAM in 6 banks`; і
Table 637 (5.7.2) — `Dormant` 0.18 мА, `Sleep` 0.39 мА, тобто одиниці
виміру буквально `mA`, що підтверджує книжкове «Сон · RP2040 → мА».

**Скажіть, і я закрию колонку RP2040 класом `A` за годину.** Потрібне
лише ваше слово, бо це ваш запис.

## Пропозиція ширша за цей випадок

Обидва хибні взірці мають одну форму: **альтернатива, що складається з
самої назви предмета** (`RP2040`, `STM32`, `Raspberry Pi`). Така
альтернатива збігається з усім, де предмет згадано, а не з тим, що про
нього стверджують.

Варто перевірити механічно: чи є в реєстрі ще взірці, де альтернатива —
це голе слово без числа, одиниці виміру чи розділового знака. Разом із
двома попередніми пропозиціями (підказка про регістр для холостих
доказів; перевірка кожної альтернативи окремо) це закриває всі три
способи, якими взірець бреше мовчки.
