# Зв'язок між супровідниками

Каталог для узгодження роботи, що йде **паралельно** — у різних сесіях,
на різних машинах, у різних гілках.

## Хто є хто

| | Хто | Де працює | Що має, чого не має інший |
|---|---|---|---|
| **М1** | головний супровідник | контейнер збирання | увесь інструментарій, збирання PDF, право на текст книги |
| **М2** | супровідник номер два | окрема фізична машина | **відкритий доступ до мережі** |

Асиметрія одна, і вона визначає весь поділ: у контейнері М1 політика
egress відповідає `403` на `espressif.com`, `bosch-sensortec.com`,
`analog.com`, `ti.com`, `nxp.com`, `semtech.com`, `datasheets.raspberrypi.com`
і решту доменів виробників. Через це **169 тверджень книги від 13
джерел** лежать у класі `C` — «джерело існує, але звідси не дістається».

Закрити їх може лише той, хто має доступ. Це і є робота М2.

## Головне правило поділу

**Кожен файл має рівно одного власника на запис.** Гілки зливаються без
конфліктів не тому, що ми обережні, а тому, що не пишемо в те саме.

| Шлях | Пише | Примітка |
|---|---|---|
| `factcheck/dokazy/m2-*.yaml` | **М2** | нові файли; додавання, не редагування |
| `factcheck/SPROSTOVANE-m2.md` | **М2** | свій реєстр спростованого |
| `zvyazok/*-m2-*.md` | **М2** | повідомлення (`PROTOKOL.md`) |
| `reviews/*-m2-*.md` | **М2** | звіти проходів |
| `manual/43-lora.md` | **М2** | зарезервовано, див. нижче |
| `manual/51-payannya.md` | **М2** | зарезервовано |
| `manual/53-akum.md` | **М2** | зарезервовано |
| `manual/54-korpus.md` | **М2** | зарезервовано |
| `zvyazok/*-m1-*.md` | **М1** | повідомлення (`PROTOKOL.md`) |
| **усе інше** | **М1** | текст книги, інструменти, шаблони, реєстр |

### Чому текст книги майже весь за М1

Не з недовіри. Кожен прохід М1 зачіпає книгу впоперек — виправлення в
розділі тягне картку, додаток і `docs/fakty.md`. Якби обидва правили
прозу, конфлікти були б не в рідкісних файлах, а в більшості.

Тому М2 **повідомляє** про знахідки, а застосовує їх М1 — крім чотирьох
зарезервованих розділів, де М2 працює від початку до кінця.

Ці чотири обрані не навмання: вони тримаються майже цілком на
недосяжних джерелах (Semtech, IEC 60529, TP4056/MAX17048, специфікації
припою) і топологічно осторонь від того, чим зайнятий М1.

## Чого не комітити ніколи

Ці файли **генеруються**. Якщо їх закомітити з обох боків, конфлікт буде
в кожному:

```
zvyazok/INDEX.md
factcheck/kartky/*.md      factcheck/manual/*.md
factcheck/dodatky/*.md     factcheck/inserts/*.md
factcheck/NARYAD-nedostupni.md
release/*.pdf   release/BUILD.txt   build/
kod/stubs/esp_idf_stubs.h
```

Запускати інструменти, що їх переписують, — можна й треба: це перевірка.
Але перед комітом:

```sh
git checkout -- factcheck/kartky factcheck/manual factcheck/dodatky \
                factcheck/inserts factcheck/NARYAD-nedostupni.md \
                release kod/stubs
```

Перегенерує й закомітить М1 — один раз, при злитті.

## Назви гілок

У тексті репозиторію вони не наводяться: політика авторства
(`.githooks/pre-push`) забороняє в змісті певні рядки, а назви гілок
цього проєкту їх містять. Тому скрізь — `git branch --show-current` і
суфікс `-m2`.

Це не формальність: хук перевіряє **вміст** кожного файлу перед
надсиланням, і коміт із назвою гілки в тексті просто не піде.

## Обмін

**Одне повідомлення — один файл, з часом UTC в імені.** Правила —
`zvyazok/PROTOKOL.md`; перевіряє їх `make zvyazok`.

```
zvyazok/2026-08-26-1351Z-m1-vidpovid-fetch-a-ne-pull.md
```

Види: `pytannya`, `vidpovid`, `zvit`, `znakhidka`, `rishennya`. Перші два
з них — `pytannya` і `znakhidka` — лишаються **відкритими**, доки на них
немає відповіді, і це видно в `make check`, а `make release-check` на
цьому падає.

Тобто правило **знахідка без реакції — незавершена робота** тут не
домовленість, а перевірка. Воно діє в цьому проєкті для рецензій, і
немає причини робити виняток для листування.

Писати по ходу, не наприкінці: знахідка, про яку інший дізнався на
злитті, коштує дорожче за знахідку, про яку він дізнався того самого дня.

`m2-zvit.md`, `m2-pytannya.md`, `m1-vidpovid.md` — листування до
протоколу. Читати варто, дописувати не треба.
