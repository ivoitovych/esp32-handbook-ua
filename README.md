# ESP32: практичний довідник

Довідник українською для досвідченого програміста без embedded-бекграунду,
який завтра може опинитися в будь-якій ролі: писати код, паяти, прошивати
серіями, лагодити чуже, зібрати робочий вузол «до ранку».

Це не курс, а довідник з кількома маршрутами входу; лінійне читання —
один із них.

**Результат збирання — один PDF, придатний до друку і роздачі.**

## Збирання

```sh
make setup      # один раз у новому клоні: хуки, ідентичність, залежності
make dovidnyk   # → build/esp32-dovidnyk.pdf
```

Потрібні: `pandoc` (≥ 3.0), Python 3 з пакетами `typst` і `pyyaml`.

```sh
apt-get install pandoc
pip install typst pyyaml pillow
```

Конвеєр: Markdown → (pandoc) → Typst → PDF. Шаблон верстання —
[`typst/handbook.typ`](typst/handbook.typ), склад книги — `book.yaml`.

| Ціль | Що дає |
|---|---|
| `make dovidnyk` | **основна книга**: A5, усе разом, поле на підшивку |
| `make kartky` | картки окремо: A4, одна картка = одна сторінка |
| `make proekty` | проєкти ярусу 2: A4 |
| `make check` | якорі, обсяги, авторство комітів |
| `make preview T=dovidnyk` | контактний відбиток сторінок у PNG |

## Правила, які легко порушити ненавмисно

- **Крос-посилання — на слаги, не на номери** (Р7). Номери генеруються
  при збиранні. `make linkcheck` обов'язковий перед комітом тексту.
- **Версії — у `toolchain-baseline.yaml`**, не в тексті розділів (Р4).
- **Обсяг — орієнтир, не межа** (Р9-а). Якість матеріалу вища за обсяг:
  жоден факт не викидається через те, що розділ переріс орієнтир.
  `make budgets` попереджає, але нічого не забороняє. Виняток — одна
  сторінка картки: це фізична умова аркуша, і вирішується вона поділом
  картки або винесенням глибини в додаток, а не видаленням фактів.
- **Швидкопсувне — у вкладишах** (Р5): ціни, наявність, радіонорми не
  входять в основне тіло.
- **Одна тема — один текст** (Р10): додаток розгортає картку з тих самих
  джерел, а не пише про те саме вдруге.
